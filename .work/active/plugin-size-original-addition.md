## Contract and affected interfaces

1. On the existing off-main plugin inspection pass, measure each bundle's contained regular files using metadata only. Initial limits: 4,096 entries and depth 24 per bundle, 250 ms cooperative monotonic elapsed time per bundle; 100,000 measured entries and 8 seconds cooperative monotonic elapsed time for the entire plugin measurement pass, independent of the discovery budget. Check cancellation and budgets between entries and bundles; exhausting the whole-pass budget stops further measurement but still inspects plugin identifiers and completes discovery. A single filesystem metadata call can block beyond the cooperative clock limit, so this is not a hard wall-clock guarantee. A read-only local probe counted Glow AU/VST3/AAX at 10/11/23 entries, depth 3/3/6, and 0.14/0.11/0.29 ms respectively. Never follow symlinks, read payloads, execute plugins, or trigger cloud downloads. Count hard-linked files once per bundle by physical file identity; use overflow-safe byte sums. Capture metadata while traversing and recheck those same bounded entries plus bundle root before accepting a complete result; this detects observable changes between snapshots, not concurrent mutation that leaves metadata unchanged or an atomic filesystem snapshot. Recheck cost counts toward the budgets. An inaccessible, changed, cancelled, over-budget, or otherwise incomplete bundle keeps `Asset.logicalBytes = nil` and emits a scan issue. Do not publish a partial byte sum as complete. A complete bundle reuses the optional Codable `logicalBytes` field and existing catalog inventory persistence; older saved assets still decode as unknown. File sizes retain their existing sample behavior.
2. Grouped plugin size is the sum of complete installation sizes, with overflow protection. If any installation is unknown, show an explicit partial/unknown group state and the known subtotal only as qualified detail; never display that subtotal as a complete product size. Show complete and partial states consistently in the plugin row, inspector, format sheet, accessibility, and size sorting. Unknown groups sort after complete measured groups in both directions; ties stay stable. A restored/offline catalog says saved/last measured where applicable, without pretending a fresh measurement.
3. Original `Date added` comes only from qualified `confirmedAddition` evidence via the existing date summary contract, associated with each exact current catalog node. For a grouped plugin, show the earliest qualified original date among current installations only when **every** current installation has one; otherwise show `Unknown` and explain the known-format count in existing detail. Preserve exact node identity and saved/stale qualification on reload; a new format without evidence makes the group unknown rather than inheriting a sibling's date. Glow remains Unknown after initial scan, rescan, receipt collection, and use collection. Preserve `presentBy` and `observedArrival` in the catalog, but label them separately as first indexed/observed arrival in existing inspector and per-format detail. Preserve receipt dates as recorded installation/update. Exact confirmed addition displays its actual date and sorts as a known original date. Unknown originals sort last; do not sort by scan bounds under the Date added heading. Instrument dates remain independent.
4. Update the existing design/feature registry and the date precision guidance to match the user-owned meaning of Date added; no new settings, persistence schema, navigation column, or GUI framework. Avoid a new persistent state field unless the complete/unknown `logicalBytes` contract proves insufficient in review.
