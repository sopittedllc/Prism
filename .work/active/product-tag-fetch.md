# Automatic product tag fetching

Driver Codex, risk2, stateful-feature/UI. User clarified metadata pulls mean automatic online fetching, not more dropdowns. Preserve asset-priority UI changes; actual usage/install dates remain separate pending capabilities.

## Contract and scope
Provide optional automatic source-specific online enrichment for exactly recognized plugins/libraries, starting with verified official sources for Spitfire Audio, Orchestral Tools, Cinematic Studio Series and one plugin vendor. Supported source descriptors list exact maker/name aliases and canonical HTTPS endpoints; no fuzzy matches, edition stripping, arbitrary crawling or installed inventory uploads. Samples and individual patches do not inherit product-level claims. Unsupported products retain local tags and show no supported source. Real content installation/usage is never inferred from a website.

Use bounded product JSON/JSON-LD or product-specific page excerpts, rejecting identity mismatches, missing selectors and unexpected response schemas. Initial provider admission uses reviewed product-specific description/section fingerprints paired with reviewed musical fields. Fetch validates identity and the normalized description SHA-256 before admitting those suggestions. Changed, negated, companion-product or bundle descriptions do not match the reviewed fingerprint and yield a visible review-needed result; no keyword guessing over prose. No full vendor text is shipped, only digest and extracted short taxonomy values. This deliberately limited initial coverage requires a new reviewed descriptor for new products or changed content. No site-wide nav/footer or administrative store tags. Product-level suggestions are described as vendor suggestions, not verified installed patch capabilities. Existing explicit edits, including empty suppression, override online suggestions. Fetch records retain canonical source URL, retrieval date and extracted fields only, not whole pages.

## State and interfaces
- New core ProductTags service: immutable known-source descriptors, conservative matching using library maker/name or plugin bundle namespace/name, bounded parser and HTTPS client; cancellation; no cookies/credentials/redirect to non-approved origin; maximum2MiB response,15s request/30s resource, one attempt per distinct recognized source in a finite snapshot (descriptor registry capped at64), sequential off-main async network. Fresh cache hits do not request the network. Every queued source is attempted even after earlier failures; status reports completed/total and cancellation preserves completed results. No retry loop; explicit Retry or later scan starts a new pass. A25-source fixture must attempt all25, including when source1fails. CacheTTL7days, failed refresh preserves prior cache with retrieval date. No negative-result permanent cache.
- Version1 atomic local tag sidecar store, injected into CatalogModel and application/demo; absent store means session-only. Validate all cached fields, source IDs/URLs, dates, size and version before use; corrupt/future cache left unchanged with visible error. No SQLite schema migration or settings serializer invention.
- Setup persisted boolean online_tags defaultfalse, registry complete; checkbox “Fetch product tags online” explains official product-page requests only, no local paths. Toggle enables fetching recognized current catalog and future completed scans/restores. Disabled cancels fetch and excludes online suggestions (cache retained); reset disables. Fetch status reports matched/succeeded/unsupported/failure with retry. User edits remain usable during fetch. Result merge invalidates filter/outline caches and recomputes metadata. Avoid late results after toggle/reset; generation token.
- New plugin Function musical facet for effect type, with robust category-specific menu indexing. Existing field defaults missing means suggested; editor Suggested restores effective online/local suggestions, never destroys explicit edits.
- Source link/date shown in technical details and a short “Vendor suggestions” provenance marker in main tags. Product tag lookup should not depend on private filesystem paths being sent. Manual retry fetch is source-only, not a whole scan.

## Acceptance
Positive real-network fixture for each admitted provider; synthetic deterministic negative tests for mismatch, unknown edition/maker, admin/navigation contamination, redirects, malformed/oversize/error/offline/cancel boundaries where applicable. Exact match only; no child patch promotion. Override precedence and disable/reset/reopen demonstrated. UI states loading/unsupported/failure/cached/no tags are inspectable and retryable. New state registry and documented privacy/persistence/reset policies agree. Fake-data demo needs explicit synthetic identities and injected provider fixtures or real vendor products labeled demo, never pretending fictional demo products exist online.
