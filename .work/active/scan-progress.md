# Live scan progress
Acting client Codex. User requests percentage/time feedback during very long scans.

Scope: optional Sendable Scanner progress callback. Single filesystem discovery queues bounded work; discovery reports count/path with no invented denominator. Inspecting metadata/project candidates has known total and a real per-stage percentage. Matching references reports its own bounded units. Finish emits complete. No duplicate pre-count traversal. Prefetch resource properties during enumeration. UI banner shows phase, determinate/indeterminate bar, counts, current item and elapsed time. Progress callbacks throttled (250ms), phase boundaries forced; UI update path does not reload/sort catalog. Session derived state only, no user setting/registry field. Keep prior results available. Ignore late callbacks after scan completion and out-of-order updates. No ETA promise, cancellation or removal changes.

Acceptance: existing scanner outputs and bounds unchanged; phases monotonic within stage; inspected completed<=total and completion emitted on empty/error/truncated scan; slow discovery reports before finishing; callbacks run off main thread; UI retains selection and responds during scans; actual runtime banner/screenshots and all tests pass. Original alpha-preserved icon restoration is retained and verified in same final package.

Plan: critic; implement core progress/model bridge/banner; meaningful progress tests and UI smoke; package and independent review. Verify swift build/test, CLI integration, state contract, native UI smoke. Current Mac only; avoid additional reads of user's large archive for cosmetic validation. No new privacy/serialization surfaces. Independent fresh review required. Existing research includes Apple progress guidance, Finder explicit operation status and DaisyDisk scan-scope feedback; previous native design system reused.
