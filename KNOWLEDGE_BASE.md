# Knowledge Base

Store only evidence-backed, reusable project knowledge. Plans say what we intend;
this file says what experience proved.

## Entry template

### KB-001: Short pattern name

- **Status:** Proposed | Validated | Superseded
- **Date:** YYYY-MM-DD
- **Area:** Architecture | Build | Runtime | Hardware | UI | UX | Accessibility | Audio | Testing
- **Evidence:** test, incident, benchmark, source file, or authoritative documentation
- **Problem:** What repeatedly went wrong or was difficult?
- **Pattern:** What should future work do?
- **Why:** What mechanism makes the pattern work?
- **Limits:** When does it not apply?
- **Related:** Links to code, plan, incident, and external documentation.
