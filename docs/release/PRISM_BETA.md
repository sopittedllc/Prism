# Prism direct-distribution beta

This is a bounded release procedure for the SwiftPM macOS app. The local package and DMG checks are safe preparation; only the release owner uses the Developer ID certificate, Keychain notary profile, GitHub, and repository visibility controls. Never copy Projector credentials, team constants, Dropbox links, or local audio into this repository.

Version metadata is in `release/beta.json`. The `CFBundleShortVersionString` is the three-part numeric date, while `CFBundleVersion` is a unique numeric date/time build supplied at packaging. The beta suffix belongs to the DMG name, Git tag and release title. The bundle ID is `llc.sopitted.Prism`; the ordinary local preview still defaults to `llc.sopitted.Simplify.preview`. This build is arm64 and declares macOS 13 minimum. Only macOS 26.7 Apple Silicon has runtime validation so far.

1. Freeze source and run the configured build, unit, integration, static, state, performance/memory and synthetic native runtime gates at one content fingerprint. Audit the exact commit manifest and public history for credentials, user paths, local captures, catalog databases and logs. Keep `.workflow/evidence/live-scan-memory`, `.workflow/evidence/fresh-onboarding-launch`, `captures/`, `build/`, and `release-build/` out of Git.
2. Build the release executable in a fresh isolated SwiftPM scratch path (`swift build -c release --scratch-path release-build/clean-scratch`), then package a **separate** `release-build/Prism.app` with `scripts/build_app.py --scratch-path release-build/clean-scratch --output release-build/Prism.app --version 2026.10.07 --build-number <YYYYMMDD.HHMM> --bundle-id llc.sopitted.Prism --signing-identity <Developer-ID-Application-identity>`. The tool enables hardened runtime and a trusted timestamp for Developer ID. Confirm the certificate Team ID matches the `notary` Keychain profile, and verify the app and every bundled executable. Do not alter the app after signing.
3. Put that signed app in a ZIP suitable for Apple’s notary service. The release owner submits it with the `notary` Keychain profile, requires **Accepted**, inspects the submission log, staples the app, and validates the stapled app with `codesign` and Gatekeeper. A rejected, unstapled or ad-hoc app is not ready for testers.
4. Run `scripts/build_beta_dmg.py --app release-build/Prism.app` **after** stapling the app. It copies that exact app and creates an Applications drop link, verifies the image, mounts it read-only and checks the contents. Sign the DMG with the same Developer ID if using a signed image, submit the **exact** DMG, require **Accepted**, inspect its log, staple and validate the DMG. Never rebuild the DMG after its notarization. Verify its mounted app, image integrity, signatures, Gatekeeper assessment, and SHA-256 **after** stapling.
5. The release owner reviews the clean commit and public-history audit, commits only the explicit allowlist, then handles any authorized public visibility, tag, push and GitHub beta release. Upload the final post-staple DMG bytes and verify the public asset hash. Attach `release/notes-2026.10.07-beta.1.md`. A local DMG, successful build, or notary submission alone is not a shipped beta.

The documented sequence follows [Apple notarization](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution), [custom nested-container workflow](https://developer.apple.com/documentation/security/customizing-the-notarization-workflow), and the existing Projector direct-distribution pattern. No step installs or replaces the already running user app; the parked Application Support backup remains untouched.
